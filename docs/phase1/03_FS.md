## 2. Job theo lịch (Roadmap 1.8, ADR-018)

### FR-20 Khai báo và chạy job — TC-J2

- `jobs.toml` (`LFMAP_JOBS` ghi đè): `[[jobs]]` với `id` (`^[a-z][a-z0-9-]*$`, duy nhất), `plugin`, `operation`, `input`, `schedule` đúng một trong `daily = "HH:MM"`, `weekly = "MON HH:MM"`, `every_minutes = 1..1439`, `max_tier` 0|1, `enabled`. Khóa lạ, id trùng, TOML hỏng → `invalid_input`; thiếu file → không có job.
- `lfmap jobs list [--json]`; `lfmap jobs run <id> [--json]` chạy với `channel = "job"`; job tắt, id không có, plugin/operation không có, input sai schema → `invalid_input`/`not_found` trước khi chạy.
- Code: `core/jobs.py`, `core/cli.py` · Test: TC-201.

### FR-21 Đăng ký Task Scheduler và script chạy — TC-J1, TC-J2, PR #34

- `task_command`: `schtasks /Create /TN "\LFMAP\<id>" /TR "<pwsh đầy đủ> -NoProfile -File <script> -JobId <id> ..." /SC DAILY|WEEKLY|MINUTE ... /F`; `/TR` tối đa 261 ký tự.
- `lfmap jobs register [--dry-run] [--repo] [--uv] [--pwsh]`: tạo/cập nhật task cho job bật, xóa task của job tắt hoặc đã bỏ; chỉ đụng task trực tiếp trong `\LFMAP\`; `--dry-run` chỉ in. Không có `schtasks` → lỗi (trừ `--dry-run`, vẫn in lệnh tạo).
- `pwsh` ghi bằng đường dẫn đầy đủ: `%ProgramFiles%\PowerShell\7\pwsh.exe`, rồi alias Store `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`, rồi `PATH` (sửa lỗi `0x80070002`).
- `scripts/Invoke-LfmapJob.ps1 -JobId <id> [-RepoPath] [-UvPath]`: chạy `uv run --directory <repo> lfmap jobs run <id> --json`, nối một dòng JSON (`started`, `finished`, `job`, `exit_code`, `stdout`/`stderr` cắt 4000 ký tự) vào `logs\jobs-YYYY-MM-DD.jsonl`, trả đúng exit code; không tìm thấy uv → exit 2.
- Code: `core/jobs.py`, `scripts/Invoke-LfmapJob.ps1` · Test: TC-201, TC-912.

### FR-22 Kênh job và hàng đợi phê duyệt — TC-J3

- `job_decision(policy, plugin, op, tier, max_tier)`: T0 → chạy; T1 với `max_tier = 1` và policy `allow|audit` → chạy + audit; `deny` → từ chối, không xếp hàng; còn lại → `queue`. Job không hỏi, bỏ qua grant, `--approve`, đích duyệt trước.
- Xếp hàng: file `approvals\pending\<UTC>-<job>-<uuid8>.json` (`id, created, expires, job, plugin, operation, input, tier, reason, detail, preview=None`); đề xuất giống hệt còn chờ được dùng lại; job trả `ToolError("permission_denied", "Queued for approval", {"approval_id": ...})`, exit 1. Input sai schema bị từ chối trước khi xếp hàng.
- `approvals pending [--json]`: đề xuất còn hạn; hết hạn (`approval_ttl_days`, 1–30, mặc định 7) chuyển sang `expired`.
- `approvals approve <id>`: chỉ TTY; id phải khớp mẫu trước mọi I/O; in tóm tắt (ký tự điều khiển được làm hiện ra), hỏi; trả lời "không" → vẫn `pending`; đồng ý → chuyển sang `done` rồi chạy đúng plugin/operation/input với kênh `cli`, quyền của job cộng tầng đã ghi; cần tầng cao hơn thì hỏi lại; ghi audit.
- `approvals reject <id>`: chỉ TTY, chuyển sang `rejected`, audit. File đề xuất không bao giờ bị xóa; file giả mạo hoặc sửa tầng thấp hơn tầng khai báo không được duyệt.
- MCP không có tool duyệt nào.
- Code: `core/approvals.py`, `core/approval.py::job_decision`, `core/cli.py` · Test: TC-202, TC-913.

## 4. lfmap-knowledge 0.1.0 (Roadmap 1.4, 1.5)

Chung: `fs_read = ["${knowledge}"]`, `fs_write = ["${data_dir}"]`, `network = true` (chỉ Ollama loopback). Mọi operation `side_effects = "none"` (ADR-016). Settings: `ollama_url` (chỉ `127.0.0.1`, `::1`, `localhost`), `embed_model` (`bge-m3`), `sensitivity` theo root, `exclude`, `max_file_bytes`, `include_cloud_files`, `ocr`.

### FR-28 Catalog và quét thư mục

- Schema SQLite v1 (`01_Architecture.md` §5.2), WAL, `busy_timeout = 5000`, `foreign_keys`; kết nối readonly không ghi được; `migrate` chạy lại không lỗi.
- `writer_lock`: khóa file không chờ (`msvcrt` trên Windows, `fcntl` nơi khác); process thứ hai → `backend_unavailable`, `details.reason = "indexer_busy"`; khóa nhả sau lỗi.
- Scanner: BLAKE2b-256 khối 1 MB chỉ cho file mới hoặc đổi; bỏ `.git`, `node_modules`, `.venv`, `AppData`, `.ssh`, `*.kdbx`, `.env`, file ẩn/hệ thống, tên bắt đầu bằng `.` hoặc `~$`; không vào thư mục liên kết; file OneDrive chỉ-trên-cloud → `skipped/cloud_only` (trừ khi `include_cloud_files`); quá cỡ → `skipped/too_large` không hash; định dạng lạ → `skipped/unsupported_format`.
- Code: `kn/store.py`, `kn/scanner.py` · Test: TC-402, TC-403.

### FR-29 Trích xuất, chunk, FTS, embed, vector

- Trích: `markitdown.convert` qua `context_for`; `extractor_version = markitdown/<backend_version>/<plugin_version>`, đổi thì trích lại; cache `cache\md\<hash[:2]>\<hash>.md` ghi nguyên tử, sidecar hỏng thì trích lại; markitdown từ chối có `reason_code` → `skipped/<reason_code>`; lỗi khác → `attempts += 1`, 3 lần → `error/extract_failed`.
- Chunk: theo heading ATX, `heading_path` "A > B", gộp tới ~1500 ký tự, tối đa 3000, cắt ở ranh giới câu rồi cắt cứng; bảng ≤ 3000 giữ nguyên, bảng dài cắt theo dòng và lặp tiêu đề; `text[char_start:char_end] == chunk.text`; không overlap.
- FTS: `fold(s) = casefold + đ→d`, tokenizer `unicode61 remove_diacritics 2`; mỗi từ truy vấn bọc nháy kép (vô hiệu cú pháp FTS5); truy vấn rỗng → `invalid_input`; mọi từ phải khớp.
- Embed: `POST {ollama_url}/api/embed` lô 32, timeout 120 s, `require_network()` trước, không dùng proxy môi trường; không kết nối được → `backend_unavailable/ollama_unreachable`; sai số vector → lỗi.
- Vector: LanceDB một bảng mỗi model; upsert theo `chunk_id`; cosine; `delete_content` kiểm hash 64 hex; ANN `IVF_HNSW_SQ` từ 50.000 dòng.
- Code: `kn/extract.py`, `kn/chunker.py`, `kn/fts.py`, `kn/embed.py`, `kn/vectors.py` · Test: TC-404 … TC-408.

### FR-30 `reindex` và `status`

- `reindex{root="", full=false}` → `{scanned, new, changed, unchanged, deleted, skipped, extracted, embedded, errors, duration_s, embed_skipped_reason}`; thuật toán `01_Architecture.md` §4.3. `root` phải là một root knowledge, không thì `invalid_input`.
- Hai file giống hệt → một dòng `contents`; file đổi thay nội dung cũ; file xóa → `deleted`, nội dung mồ côi bị GC (chunks, FTS, vector).
- Ollama tắt → không lỗi, chỉ mục chỉ có từ khóa; model embedding mới → embed vào bảng riêng.
- Kênh `cli`: dòng tiến độ `<stage> <done>/<total>` ra stderr (stdout `--json` sạch).
- `status` → `{roots[{path, sensitivity, last_scan, files}], files_by_status, chunks, embed_model, ollama_available, indexer_busy}`; dùng kết nối readonly, không lấy khóa; chạy được trước lần reindex đầu.
- Code: `kn/indexer.py`, `kn/tool.py` · Test: TC-409, TC-413, TC-915.

### FR-31 `search_files` và `get_file`

### FR-32 `search`

- `search{query, root, modified_after, mode=hybrid|keyword|vector, limit}` → `{query, hits[ChunkHit], untrusted=true, notice}`; `ChunkHit`: `path, heading_path, snippet (300 ký tự), score, chunk_id, char_start, char_end, mode_used, duplicates`.
- `keyword`: FTS5 bm25; `vector`: cosine LanceDB, Ollama hoặc vector store thiếu → `backend_unavailable`; `hybrid`: RRF `Σ 1/(60 + rank)` trên top `4 × limit` mỗi bên, lùi về keyword khi Ollama/vector thiếu (`mode_used = keyword`).
- Chunk → file `indexed` đầu tiên theo `rel_path`; các file cùng nội dung vào `duplicates`; bỏ file `deleted` và hit vector có `chunk_id` không còn.
- Code: `kn/search.py::search` · Test: TC-412, TC-414.

### FR-33 `get_context`

### FR-34 `related` và cạnh

- `GENERATED_FROM`: `X.md` ↔ `X` hoặc `X.<ext>` cùng thư mục, cùng root, bỏ file `deleted`; idempotent.
- `REFERENCES`: link Markdown tương đối trong Markdown đã trích, chuẩn hóa dạng chuỗi, phải nằm trong cùng root; bỏ link UNC, tuyệt đối, ổ đĩa, có scheme (cả sau percent-decode), link tới file thiếu/đã xóa/chính nó; reindex thay cạnh cũ.
- `related{path, limit}` → `{path, related[{path, reason, score}]}`; `reason` ∈ `duplicate (1.0), generated_from (0.9), references (0.8), referenced_by (0.7), similar_content (cosine vector trung bình), same_folder (0.1)`; lý do mạnh nhất thắng; không trả chính nó hay file `deleted`; không có vector vẫn chạy.
- Code: `kn/edges.py` · Test: TC-411, TC-414.

### FR-35 Độ nhạy và nhật ký dữ liệu rời máy — Exit criteria

- Root ẩn trên `mcp`/`rest` = root `secret` trong catalog + root không còn trong danh sách root cấu hình không-secret (root vừa đổi sang `secret` hoặc vừa bị bỏ bị ẩn trước lần reindex sau). Trên `cli`/`sdk` không ẩn gì.
- Áp cho mọi operation: kết quả, `duplicates`, file liên quan, bộ lọc `root` (lọc theo root ẩn → `not_found`), `get_file`/`related` của file trong root ẩn → `not_found`. Nội dung chỉ có trong root `secret` không lọt qua vector.
- `egress_log`: mỗi lời gọi `search`/`get_context` trên `mcp`/`rest` có ít nhất một hit ghi đúng một dòng `ts, channel, operation, file_ids, chunk_ids, bytes` (byte UTF-8 của văn bản trả). Kênh local hoặc kết quả rỗng không ghi.
- Mọi output `search`/`get_context` có `untrusted = true` và `notice`; mô tả MCP của operation nói kết quả là dữ liệu, không phải chỉ dẫn.
- Code: `kn/search.py` (`hidden_root_ids`, `_log_egress`), `kn/tool.py::_shown_roots` · Test: TC-412, TC-414, TC-916.
