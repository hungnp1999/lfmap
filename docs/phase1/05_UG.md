# LFMAP Phase 1 — Hướng dẫn sử dụng (UG)

Phiên bản 0.9 bản nháp · 2026-10-22 · Áp dụng cho lfmap-core 0.2.0, lfmap-markitdown 0.1.0, lfmap-knowledge 0.1.0 (mốc `b002710`). Shell: PowerShell 7.

Phần cài đặt, quy ước CLI chung và SDK cơ bản không đổi: xem `docs/phase0/05_UG.md`. Tài liệu chi tiết bằng tiếng Anh: `packages/lfmap-knowledge/README.md`, `plugins/lfmap-markitdown/README.md`, `docs/jobs.md`.

## 1. Cài đặt và cập nhật

```powershell
Set-Location D:\Development\lfmap
git pull
uv sync                      # cài core, echo, markitdown, knowledge
uv run pytest -q             # toàn bộ phải pass (một số test OCR/Windows bị skip là bình thường)
uv run lfmap plugins list    # echo, knowledge, markitdown
uv run lfmap plugins health
```

- Nếu `uv sync` báo `lfmap.exe` đang bị khóa: đóng Claude Code/Claude Desktop (MCP server đang chạy) rồi chạy lại.
- Tùy chọn OCR (PDF scan, ảnh): `uv sync --all-packages --extra ocr` và cài Tesseract (`winget install UB-Mannheim.TesseractOCR`). Tesseract từ winget chỉ có `eng`, `osd`; muốn tiếng Việt thì chép `vie.traineddata` vào một thư mục và đặt `tessdata_dir` (mục 2).
- knowledge cần Ollama đang chạy và model embedding: `ollama pull bge-m3`.

## 2. Khai thư mục và cấu hình

Khai thư mục ở terminal (lệnh chỉ chạy khi anh ngồi gõ, agent không tự gọi được):

```powershell
uv run lfmap config add-folder D:\Docs --as documents          # markitdown đọc
uv run lfmap config add-folder D:\Docs\_markdown --as exports  # markitdown ghi
uv run lfmap config add-folder D:\Docs --as knowledge          # knowledge lập chỉ mục
uv run lfmap config path                                       # kiểm tra lại root của từng plugin
```

Phần còn lại sửa tay trong `%LOCALAPPDATA%\lfmap\config.toml`:

```toml
[plugins.markitdown.settings]
ocr_languages = "vie+eng"
tessdata_dir = 'D:\Tools\tessdata'

[plugins.knowledge.settings]
ollama_url = "http://127.0.0.1:11434"   # chỉ nhận localhost
embed_model = "bge-m3"

[plugins.knowledge.settings.sensitivity]   # mặc định "normal"
'D:\Contracts' = "private"   # trả cho Claude, có ghi egress_log
'D:\HR' = "secret"           # không bao giờ trả qua MCP

[approval]                   # tùy chọn, mặc định như dưới
T1 = "audit"
T2 = "ask"
T3 = "ask"
```

## 3. Phê duyệt: khi nào LFMAP hỏi anh

| Tầng | Ví dụ | Mặc định |
|---|---|---|
| T0 | `convert`, `search`, `knowledge reindex` (chỉ ghi chỉ mục riêng) | Chạy |
| T1 | `markitdown export` tạo file `.md` mới | Chạy và ghi `audit.jsonl` |
| T2 | `export --overwrite` (ghi đè) | Hỏi: prompt ở terminal (`--yes` để bỏ qua); qua Claude là hộp thoại xác nhận nếu client hỗ trợ |
| T3 | Gửi dữ liệu ra đích chưa duyệt, API trả phí | Chỉ khi anh cấp quyền có thời hạn hoặc trả lời prompt ở terminal |

```powershell
uv run lfmap approvals grant markitdown.export --for 2h   # cho phép trong 2 giờ (T3 tối đa 24h, T1–T2 tối đa 7 ngày)
uv run lfmap approvals list
uv run lfmap approvals revoke markitdown.export
uv run lfmap audit tail -n 20                              # xem lại những gì đã chạy/bị từ chối
```

Cho Claude ghi đè trong một phiên làm việc: khởi động MCP với `--approve markitdown.export` (hiệu lực 8 giờ, không áp cho T3).

## 4. Chuyển tài liệu sang Markdown (markitdown)

```powershell
uv run lfmap markitdown classify --path D:\Docs\bao-cao.pdf
uv run lfmap markitdown convert --path D:\Docs\bao-cao.docx --json
uv run lfmap markitdown convert --path D:\Docs\scan.pdf --ocr --ocr-languages vie+eng
uv run lfmap markitdown export --path D:\Docs --output-dir D:\Docs\_markdown --recursive
uv run lfmap markitdown info
```

- `classify` cho biết file có chuyển được không, có cần OCR không (`reason_code`).
- `export` ghi `<tên.đuôi>.md`; file đã có bị bỏ qua (`exists`) trừ khi `--overwrite` (sẽ hỏi một lần).
- `.doc`, `.rtf`, `.odt`, `.ppt`, `.odp`, `.ods` chỉ chuyển được bằng app MarkitdownTool (`office_gui_only`).

## 5. Lập chỉ mục và tìm tài liệu (knowledge)

```powershell
uv run lfmap knowledge reindex --json        # lần đầu lâu (trích + embed); lần sau chỉ kiểm thay đổi
uv run lfmap knowledge status --json
uv run lfmap knowledge search_files --query "bao cao" --ext pdf
uv run lfmap knowledge search --query "hợp đồng bảo trì" --limit 5
uv run lfmap knowledge get_context --question "Điều khoản thanh toán là gì?" --token-budget 2000
uv run lfmap knowledge related --path D:\Docs\hop-dong.docx
```

Tên lệnh là đúng tên operation (có gạch dưới); tên option đổi `_` thành `-` (`--token-budget`).

- Tìm không dấu được ("hop dong" khớp "Hợp đồng"), nhưng "ma" khớp cả "mà/má/mã"; chế độ `hybrid` (mặc định) dùng thêm tìm theo nghĩa để thu hẹp.
- Ollama tắt: `reindex` vẫn chạy và báo `embed_skipped_reason`; `search` tự lùi về tìm từ khóa.
- Chỉ mục nằm ở `%LOCALAPPDATA%\lfmap\knowledge\`. Xóa `vectors\` là an toàn: lần `reindex` sau embed lại, không trích lại. `--full` dựng lại toàn bộ từ cache.
- Một lần chỉ một `reindex`; lần thứ hai báo `indexer_busy`.

## 6. Hỏi tài liệu qua Claude

```powershell
claude mcp add lfmap -- uv run --directory D:\Development\lfmap lfmap serve mcp --plugins knowledge markitdown
claude mcp list        # lfmap: ... Connected
```

Hỏi Claude bình thường, ví dụ "Trong tài liệu của tôi, hợp đồng bảo trì quy định thanh toán thế nào? Trích dẫn nguồn." Claude gọi `knowledge_get_context` hoặc `knowledge_search` và trích đường dẫn + heading.

Kiểm tra dữ liệu đã gửi cho Claude:

```powershell
uv run python -c "import sqlite3,os; c=sqlite3.connect(os.path.expandvars(r'%LOCALAPPDATA%\lfmap\knowledge\catalog.db')); [print(r) for r in c.execute('select ts, channel, operation, bytes from egress_log order by ts desc limit 10')]"
```

- Root `secret` không bao giờ đi qua MCP, kể cả khi anh vừa đổi cấu hình mà chưa reindex.
- Kết quả luôn có `untrusted = true`: đó là trích đoạn tài liệu, Claude không nên làm theo như chỉ dẫn.

## 7. Job theo lịch

1. Khai job trong `%LOCALAPPDATA%\lfmap\jobs.toml`, ví dụ reindex mỗi giờ:

   ```toml
   [[jobs]]
   id = "knowledge-reindex"
   plugin = "knowledge"
   operation = "reindex"
   input = {}
   schedule = { every_minutes = 60 }   # hoặc { daily = "07:30" }, { weekly = "MON 07:30" }
   max_tier = 0
   enabled = true
   ```

2. `uv run lfmap jobs list`, rồi `uv run lfmap jobs run knowledge-reindex` để thử tay.
3. `uv run lfmap jobs register --dry-run`, rồi `uv run lfmap jobs register` (task nằm trong `\LFMAP\` của Task Scheduler).
4. Muốn chạy cả khi đã khóa máy/đăng xuất: Task Scheduler → `LFMAP` → task → General → "Run whether user is logged on or not" (nhập mật khẩu Windows); Conditions → "Wake the computer to run this task". Làm lại sau mỗi lần `register`.
5. `uv run lfmap jobs doctor` kiểm máy (chỉ đọc). Log mỗi lần chạy: `%LOCALAPPDATA%\lfmap\logs\jobs-YYYY-MM-DD.jsonl`.

Job gặp việc vượt `max_tier` (vd ghi file khi `max_tier = 0`) không chạy mà để lại đề xuất:

```powershell
uv run lfmap approvals pending
uv run lfmap approvals approve <id>   # xem, gõ y; chạy đúng một lần
uv run lfmap approvals reject <id>
```

Đề xuất hết hạn sau 7 ngày (`[jobs] approval_ttl_days`). Duyệt chỉ làm được ở máy, không qua Claude.
