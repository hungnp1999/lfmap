# Bàn giao: vòng lặp qwen tự động (qwen-loop)

Ngày chốt: 2026-10-21 (Hùng chọn phương án B). Roadmap: hạng mục 1.7 "Quy trình Planner → Task Card → Local Agent → Review". Liên quan: [`2026-10-20-knowledge-k4-k14.md`](2026-10-20-knowledge-k4-k14.md) (task 2 ở đó được thay bằng vòng lặp này).

## Bối cảnh

qwen2.5-coder:14b chạy tốt trên DIEP-ANH: khoảng 35–40 tok/s, VRAM đỉnh khoảng 12,3 GB ở ngữ cảnh 16k. Chất lượng đủ dùng cho card nhỏ có test viết sẵn. Nút thắt tiến độ hiện nay là hạn mức Claude Pro.

Hiện vòng qwen chạy bằng tay: Hùng chạy `Ask-Qwen.ps1`, Claude lấy câu trả lời, áp code, chạy test, soạn prompt sửa lỗi, rồi lặp lại. Phần "chuyển tay" này tốn cả thời gian của Hùng lẫn token Claude, nhưng không cần suy luận.

Số đo K1–K3 cho thấy qwen chưa tự làm xong card: K1 phải sửa tay 4 chỗ, K2 2 chỗ, K3 phải viết lại. Vì vậy mục tiêu ở đây là tự động hoá phần chuyển tay và đo chính xác qwen tự làm được bao nhiêu. Mục tiêu không phải thay vai trò review của Claude.

## Mục tiêu

Một lệnh chạy được cả đợt card (ví dụ K4–K7) không cần người hay Claude can thiệp giữa chừng. Mỗi card cho ra một gói gồm diff, log từng vòng và báo cáo, để Claude Code review gộp một lần.

Tiêu chí hoàn thành, kiểm tra được:
- `qwen_loop.py run <card-dir>...` chạy tuần tự các card. Mỗi card dừng khi xanh, khi hết số vòng, hoặc khi không còn tiến triển.
- qwen không ghi được file nằm ngoài `targets` của card, và không sửa được file test (có test chứng minh).
- Chạy lại K2 (`store.py`) từ commit trước K1–K3 cho kết quả và số đo tương đương lần chạy tay.
- Đợt K4–K7 chạy xong. Bảng `summary.csv` có cột "xanh không cần Claude sửa" cho từng card.

## Phạm vi

- Trong phạm vi:
  - Định dạng card (`card.toml` + `prompt.md`).
  - Script `qwen_loop.py` (chạy một hoặc nhiều card, sinh gói kết quả).
  - Test của script với Ollama giả.
  - Chạy thử lại K2, chạy thật K4–K7.
  - Đo đạc và quyết định có mở rộng hay không.
- Ngoài phạm vi:
  - Agent Router.
  - Agent framework.
  - Giao diện (agent console).
  - Chạy song song nhiều card (chỉ có một GPU).
  - Để qwen viết test hoặc review.
  - Dùng model cloud trong vòng lặp.
  - Tự mở PR.

## Thiết kế

```text
card-dir/ (card.toml, prompt.md)
   │
   ▼
qwen_loop.py run
   1. git worktree add <work>/<card> từ base_ref (repo lfmap)
   2. ghi hash các file test
   3. gửi prompt.md → Ollama /api/generate (127.0.0.1, num_ctx 16384, temperature 0.2)
   4. tách code block có tiêu đề đường dẫn → chỉ ghi file thuộc `targets`
   5. chạy test_cmd (pytest đúng file test của card) + ruff check + ruff format --check
   6. xanh → dừng | đỏ → prompt sửa (lỗi rút gọn, ≤ ~1,5k token, "trả lại nguyên file đã sửa") → về bước 3
   7. dừng khi: xanh / hết max_rounds / lỗi giống vòng trước / hash test bị đổi
   ▼
out/<card>/ : report.md, final.diff, round-N.prompt.md, round-N.answer.md, round-N.test.log
out/summary.csv : card, status, rounds, tok/s, wall_s, peak_vram_mb, claude_fixes (để trống, điền lúc review)
```

`card.toml` (khái niệm):

```toml
id = "TC-K4"
base_ref = "feature/knowledge-k4-k7"
targets = ["packages/lfmap-knowledge/src/lfmap_knowledge/extract.py"]
tests = ["packages/lfmap-knowledge/tests/test_extract.py"]
max_rounds = 3
```

Các điểm cần giữ:
- **Câu trả lời rỗng:** nếu qwen trả block rỗng (bài học K1–K3), gửi lại một lần với câu kết "NOW WRITE THE COMPLETE <module>.py". Lần gửi lại này không tính là một vòng.
- **Docstring:** báo cáo liệt kê docstring bị mất so với base. Script chỉ báo, không tự khôi phục.
- **Số đo:** ghi tiếp vào `hw-log.csv` theo đúng cột của `Ask-Qwen.ps1`, để so được với số cũ.
- **Mạng:** chỉ gọi URL loopback và từ chối URL khác. Dữ liệu không rời máy.

## Danh sách task

Mỗi task vừa một phiên.

1. **B1: viết `qwen_loop.py` và test (Cloud, Claude Code).**
   - Cách làm: Ollama giả bằng `http.server` trả câu trả lời dựng sẵn, repo git giả tạo trong `tmp_path`.
   - Môi trường: Cloud, vì đây là Python thuần, chạy được trên Linux, không cần GPU.
   - Xong khi:
     - Có test cho: ghi ngoài `targets` bị từ chối, sửa file test thì dừng, lỗi lặp lại thì dừng sớm, câu trả lời rỗng thì gửi lại, URL không phải loopback bị từ chối.
     - Ruff sạch.
     - Code nằm trong `/mnt/project-files/qwen-loop/` và được chép vào `D:\Development\lfmap-tools\qwen-loop\`.
2. **B2: chạy thử lại K2 (Local, Hùng tự chạy, không cần Claude).**
   - Card K2 lấy từ `phase1-knowledge/TC-K2_qwen.md`, `base_ref` là commit trước K1–K3.
   - Môi trường: Local, vì cần qwen và GPU thật trên DIEP-ANH.
   - Xong khi: có `out/TC-K2/` và số đo tương đương lần chạy tay (khoảng 35–40 tok/s, VRAM ≤ 13 GB). Lỗi của script (không phải lỗi của qwen) thì gửi lại Cloud sửa.
3. **B3: chuẩn bị card K4–K7 (Cloud, Claude Code).**
   - Gộp với task 1 của file bàn giao knowledge: test viết sẵn và prompt chuyển sang định dạng `card.toml` + `prompt.md`, mỗi prompt dưới ~4k token.
   - Môi trường: Cloud, vì chỉ viết test và văn bản.
   - Xong khi: test được commit trên `feature/knowledge-k4-k7` và đỏ đúng vì thiếu module; có 4 thư mục card.
4. **B4: chạy đợt K4–K7 (Local, Hùng tự chạy).**
   - Lệnh: một lệnh `qwen_loop.py run cards\TC-K4 cards\TC-K5 cards\TC-K6 cards\TC-K7`, chạy được khi máy rảnh hoặc qua đêm.
   - Môi trường: Local, vì cần GPU.
   - Xong khi: có `out/summary.csv`, và thư mục `out/` được chép vào `/mnt/project-files/qwen-loop/runs/2026-10-xx/`.
5. **B5: review gộp K4–K7 (Cloud, Claude Code).**
   - Đây chính là task 3 của file bàn giao knowledge, nhưng đầu vào là `final.diff` và `report.md` thay cho trao đổi qua lại. Điền cột `claude_fixes`, mở PR.
   - Môi trường: Cloud.
   - Xong khi: PR K4–K7 merge, và `summary.csv` đủ cột.
6. **B6: điểm quyết định (Hùng + cố vấn, không cần code).**
   - Từ `summary.csv`, quyết định mở rộng vòng lặp sang loại việc khác (docstring, README, K12 `catalog.py`) hay giữ phạm vi.
   - Môi trường: không cần máy, chỉ cần thảo luận.
   - Ngưỡng gợi ý: ít nhất 50% card xanh mà Claude không phải sửa logic.

## Rủi ro và điểm cần lưu ý

- **Chạy code do qwen sinh ra trên máy thật.** pytest sẽ thực thi code đó. Giảm nhẹ bằng cách: chạy trong worktree riêng, card chỉ là module thuần (không động vào hệ thống file ngoài `tmp_path`), và Hùng không chạy card có quyền ghi/xoá thật. Mức rủi ro tương đương cách đang chạy tay.
- **Tách code block sai** (qwen bỏ tiêu đề đường dẫn hoặc trả nhiều block). Quy tắc: card chỉ có một target thì nhận block Python duy nhất. Có nhiều target thì bắt buộc có tiêu đề đường dẫn, không có thì tính là vòng hỏng.
- **Lỗi rút gọn quá tay** khiến qwen sửa mò. Giữ tên test hỏng, dòng assert và cuối traceback (`--tb=short`).
- **Phình phạm vi:** đây không phải khởi đầu của Agent Router. Mọi đề xuất thêm định tuyến, nhiều model hay giao diện đều để tới spike Phase 2 (ADR-004).
- **Khoá file trên Windows:** `git worktree remove` có thể lỗi khi còn tiến trình giữ file. Script không xoá worktree, Hùng dọn tay.
