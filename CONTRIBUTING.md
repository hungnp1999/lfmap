# Contributing to LFMAP

LFMAP (product name **Lan Hài**) is developed in a private repository. Contributors join **by personal invitation** from the project owner; there is no public call for contributions yet.

> Status: draft (issue #200). The Contributor License Agreement in `docs/legal/CLA.md` is waiting for legal review. No external contribution is merged before it is final.

## Before your first pull request

1. **Invitation.** The owner adds you as a collaborator on `hungnp1999/lfmap` and gives you an issue that fits you.
2. **Sign the CLA.** Read `docs/legal/CLA.md` (English and Vietnamese), sign it once and send the signed copy to the owner. The owner keeps signed copies outside the repository and adds your name, GitHub login and signing date to `CONTRIBUTORS.md`. A pull request from someone not listed there is not reviewed.
3. **Read** `ARCHITECTURE.md`, the Plugin Contract and `CLAUDE.md` (the rules every session follows, human or AI). The smallest example plugin is `plugins/lfmap-echo`.
4. **Set up provenance** as in `docs/DEVELOPMENT_PROVENANCE.md`: ask the owner for an environment label, register an SSH signing key on GitHub and enable the commit hook.

## How work flows

- Every task is a GitHub Issue on the "LFMAP work" board. Larger tasks have a spec in `docs/specs/` and frozen tests written before the code.
- Branch from an up-to-date `main`, one task per branch, and open a pull request that says `Closes #N` and fills in the template.
- Add a line to `CHANGELOG.md` under `[Unreleased]`. A change to the module map, a main flow or an invariant also updates `ARCHITECTURE.md`.

## Commits

Every commit:

- is **signed** with a key registered on GitHub;
- ends with the trailers `Dev-Environment: <label>` and `Signed-off-by: Your Name <email>` (`git commit -s`);
- adds `Co-Authored-By:` or `AI-Agent:` when an AI tool wrote part of it. Say so honestly: AI-assisted work is allowed, but the record of who wrote what must be true (it supports copyright registration).

The `Provenance` workflow fails a pull request whose commits miss these.

## Checks (Windows, repository root)

```powershell
uv sync
uv run pytest
uv run ruff check . ; uv run ruff format --check .
uv sync --no-dev ; uv run --no-sync python scripts/check_licenses.py ; uv sync
```

CI runs the same checks plus CodeQL on Windows. A pull request is merged only when all are green and the owner (or the managing agent acting under the owner's rules) approves it. Pull requests that touch caller-supplied paths, adapters, network calls, subprocesses or `.claude/` also get a security review.

## Rules

- Code, comments, commit messages, pull requests and technical docs in **English**; discussion in Vietnamese or English.
- Business logic lives in a plugin's `Tool` class. Adapters (CLI, MCP, REST, events) are generated by `lfmap-core`; never write plugin-specific code in them.
- Standard library first. A new dependency needs an allowed permissive license (MIT, BSD, Apache-2.0; MPL-2.0 unmodified) checked **before** you add it; GPL, AGPL, LGPL, SSPL and fair-code licenses are refused.
- Every caller-supplied path goes through `PermissionManager.require_read` / `require_write` before any file-system call; UNC and device paths are refused.
- **No real data** in the repository, its history, issues or pull requests: no personal documents, company names or customer data. Tests use synthetic fixtures only.
- Never commit secrets, tokens or keys.
