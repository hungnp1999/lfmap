`lfmap backup`, `backup list` and `backup restore` (#196, docs/specs/backup.md): a dated zip of the owner state (config, jobs, flows, grants, audit log, approval queue, flow runs, SQLite snapshots of `events.db` and a content-free `catalog.db`) in the `[backup]` folder of `config.toml`, never overwritten, last `keep` zips kept, SHA-256 manifest verified before a restore, which runs only at a TTY with a typed code. `[backup] daily` adds task `\LFMAP\backup` to `lfmap jobs register`. No new dependency.
