Jobs run as one-step flows (#190, `docs/specs/flows.md` section 13): `jobs.toml` is read unchanged and each job is translated on load (`lfmap_core.jobs_flow`) into a flow with a `schedule` trigger and one step; `lfmap jobs run` is an alias of the Flows runner followed by the same event drain, and `jobs.run_job` is removed. A job above its `max_tier` now pauses behind a `flows.resume` proposal named by the job id (identical pending runs reuse it), a job run writes a run file only while it waits for approval, and its audit lines use channel `flow`. `Step` gains `via = "call"|"event"` (event steps keep both ceilings, `check_flow` refuses them for plugins without `[adapters] events`); `flows list|check` include jobs; a job and a flow may not share an id. Proposals queued by jobs before this change stay approvable through the legacy reader for one release, then it is removed. Task names, `scripts/Invoke-LfmapJob.ps1` and exit codes are unchanged; `flows_run.py` is 227 code lines (cap 230). No new dependency.
