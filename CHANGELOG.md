Deny entries are not subtracted. No new dependency.
- Jobs through the event bus (EB-5, #104): `via = "event"` in `jobs.toml` makes `lfmap jobs run` publish `<plugin>.<operation>.requested` as core after the usual checks, drain at most `--max-events`, and report the `.completed` output or the `.failed` error for that request (`timeout` when it was not handled in the drain; it stays queued). Only plugins with `[adapters] events = true` accept it (`invalid_input`, flagged by `jobs doctor`). The job's `max_tier` and `[events] max_tier` both apply, so the lower one wins. Default `via = "call"` is unchanged.
- `docs/research/2026-10-30-eventbus-eb4-smoke.md`: EventBus Windows smoke on pc-01 (EB-4). Two processes drained one durable subscription three times over 200 events with no duplicate or missing event. Two `lfmap events run --until-idle` processes answered 200 echo requests with 200 `.completed` events. `jobs run` drained within `--max-events`. No SQLite lock waits. Wall time is dominated by about 5 s of CLI start-up. It also records a pre-existing weakness: `sys.stdin.isatty()` is True for stdin redirected from `NUL` on Windows, so TTY-only commands (`approvals grant`, `events prune`, ...) run for an agent or script.
- `lfmap events status|dead|retry|prune|run` (EB-3, spec `docs/specs/events.md` section 7): `status` counts deliveries per subscription and state (new `SqliteBus.counts()`), `dead [--subscription]` lists dead letters with control characters escaped, `run [--until-idle] [--max-seconds 60]` attaches the event adapter and drains in batches. `retry <event-id> <subscription>` and `prune [--days 7]` change the queue and run only at an interactive terminal; none of these has an MCP form. `lfmap jobs run` now drains the bus after the job, also when the job fails, bounded by `--max-events` (default 1000); with no events-enabled plugin it opens nothing, and a bus error only prints a warning. The plugin guide in `packages/lfmap-core/README.md` says handlers must be idempotent; `ARCHITECTURE.md` gains the "Event" flow.
- `lfmap-core` event adapter (EB-2, spec `docs/specs/events.md` section 6): plugins with `[adapters] events = true` publish through `ctx.events` (`PluginEvents`: own `<plugin-id>.…` topics only, never operation topics, `source` = plugin id; other plugins get `permission_denied`). `open_bus()` opens `%LOCALAPPDATA%\lfmap\events.db`. `EventAdapter` subscribes `adapter-<plugin-id>` to `<plugin-id>.*.requested` (core-only requests, payload `{"input": {...}}`) and runs the operation on the new approval channel `event`, which `decide` treats like `job`: no one is asked, `[events] max_tier` in config.toml (0 or 1, default 0) caps the tier, and a call above it becomes a proposal with `job = "events"`. Success publishes `.completed` `{request_id, output}` (or `output: null, output_too_large: true` past 64 KiB); a `ToolError` publishes `.failed` `{request_id, error}`; other exceptions follow the bus retry policy. No CLI yet (EB-3).
- `lfmap-core` EventBus core (Phase 2a, ADR-021, spec `docs/specs/events.md`): dot topics with `*` / `>` patterns (`topics.py`), the `Event` model and `EventBus` Protocol with `InProcessBus` (`events.py`), and `SqliteBus` (`events_sqlite.py`): outbox write in one `BEGIN IMMEDIATE` transaction, durable named subscriptions, 60 s leases matched on a lease token, at-least-once delivery, retry with 2–300 s backoff up to 5 attempts, dead letters for `invalid_input` / `permission_denied` / `not_found`, `retry` and `prune`, several processes on one machine. Payloads are JSON objects of at most 64 KiB. Handler exceptions never stop a drain; `KeyboardInterrupt` still does. No adapter or CLI yet (EB-2, EB-3). Frozen tests from `docs/specs/events-tests/` copied unchanged.

### Fixed

- Security (#108, option 1): `approvals grant`, `approvals revoke` and `config add-folder` print a random 6-character code (no 0/O or 1/I) and run only when the person types it back; a wrong code or end of input refuses with `permission_denied`, writes nothing and is audited as `deny`. `grant` checks tier and duration before asking. On Windows the interactive check also needs `GetConsoleWindow()` to return a window, so hidden consoles of agent shells no longer count as a person. This raises the bar but does not stop an agent of the same Windows user that drives a visible console; a separate Windows user for agents is the pending ADR.
- Security: commands that must be run by a person at a terminal (`approvals grant/revoke`, `config add-folder`, `events retry/prune`, and the confirmation prompts of operation commands) ran for agents and scripts on Windows when stdin was redirected from `NUL` (`<NUL`, `</dev/null`), because `isatty()` is True for that character device. A T3 grant could be created without a person (found in the EB-4 smoke, issue #106). On Windows `cli._interactive()` now requires `GetConsoleMode` to succeed on stdin; elsewhere it keeps `isatty()`; any error counts as not interactive.
- `scripts/check_licenses.py` no longer fails when the `ocr` extra is installed: `fpdf2` and `img2pdf` (LGPL-3.0, required by `ocrmypdf` 17.13; every `ocrmypdf` since 15 needs `img2pdf`) are reviewed exceptions, used unmodified as replaceable libraries, as in MarkitdownTool. Found in the Docling real run on pc-01; CI does not install the extra.
- `lfmap-markitdown` Docling OCR with a language whose Tesseract data is not installed (for example `--ocr-languages vie`) now fails before the converter is built with `backend_unavailable` / `ocr_unavailable`, "Tesseract language data not installed: vie" and the `missing` and `installed` languages, instead of `internal` "Conversion failed: OcrLanguageNotSupportedError". When Tesseract cannot list its languages the check is skipped.
- `lfmap-knowledge` `get_context` now actually prunes weak matches (L23 follow-up). On DIEP-ANH `min_relative_score` 0.5 dropped nothing: the question rarely matches keywords, and vector-only RRF scores fall only from 1/61 to 1/80, so every hit stayed above half the best and the context still used about 3,850 of 4,000 tokens. The cut no longer uses RRF scores: each keyword and vector list is min-max scaled over its visible candidates (best 1, weakest in the pool of 80 0), and a hit is kept if it reaches `min_relative_score` in either list. Default stays 0.5; `0` keeps every hit. Chunks in hidden roots are left out of the scaling, so they cannot change what is returned. `search` is unchanged.
- `lfmap-knowledge` chunker no longer takes a sentence that markitdown turned into a heading as a section title (L20, seen on `.docx` files whose opening paragraph is in italics): a heading line longer than 120 characters, or ending with a period after 8 or more words, stays body text of the current section. Emphasis marks around the title are ignored. Existing indexes keep the old `heading_path` until `reindex` with `full`, which re-chunks from the Markdown cache without converting again.
- `lfmap-knowledge` `get_context` no longer fills `token_budget` with weak matches (L23): new input `min_relative_score` (0 to 1, default 0.5) drops hits scoring below that fraction of the best hit before packing. With hybrid ranking (RRF) and a question that matches keywords, this keeps chunks found by both keyword and vector search; a question with no keyword match keeps the old behaviour. `0` restores it everywhere.
- `lfmap-knowledge` reports an HTTP error from Ollama `/api/embed` as `embed_skipped_reason` `ollama_http_<code>` with the first 500 characters of the response body in the error details and a log warning, instead of `ollama_unreachable`. Setting `embed_concurrency` above 1 now logs a warning: Ollama serves bge-m3 with one slot even with `OLLAMA_NUM_PARALLEL=2`, so parallel requests gain nothing and some failed with HTTP 400 on the DIEP-ANH 10k bench. Default stays 1.
- Lockfile: `certifi` 2026.10.18 → 2026.10.19 (GHSA-6q48-6c7w-9gw2, Dependabot alert #1, critical). It reaches the workspace only through `markitdown` → `requests`; lfmap converts local files and does not fetch URLs with `requests`, so the bundle was not used at runtime. License unchanged (MPL-2.0).
- `lfmap-knowledge` can send several `/api/embed` requests at once: new setting `embed_concurrency` (1 to 4, default 1) for an Ollama started with `OLLAMA_NUM_PARALLEL` of 2 or more. Vectors keep the input order; the URL stays loopback-only.
- `lfmap-knowledge` reindex embeds faster (second round after the DIEP-ANH 10k bench at `955fe99`: 3.75 files/s, GPU 22–52% busy). Each Ollama `/api/embed` request now carries 128 texts instead of 32 (new setting `embed_batch`, 1 to 1024), and the next batch of about 512 chunks is embedded on a worker thread while the previous one is written to LanceDB and the catalog. A failed batch and the ones after it stay pending for the next run.
- `lfmap-knowledge` reindex embeds and writes vectors in batches of about `UPSERT_BATCH = 512` chunks gathered across files, instead of one Ollama call and one LanceDB write per file. The 10k-file bench on DIEP-ANH left 10,004 LanceDB versions after the first run and kept the GPU about 21% busy; with a fake embedder on 1,000 files the first run drops from 81 s to 29 s and the table keeps 5 versions instead of 1,003. A batch that fails (Ollama down) stays pending for the next run, earlier batches are kept. `optimize` runs only when the reindex embedded or garbage-collected something, and garbage collection deletes vectors with one filter per 500 content hashes (`LanceVectorStore.delete_contents`).
- `lfmap-knowledge` vector search selects `_distance` explicitly, so LanceDB 0.40 no longer logs its scoring autoprojection deprecation warning to stderr on every search (seen in the K14 MCP run).
- `lfmap jobs register` writes the full path of `pwsh` into each task (`--pwsh` overrides). With PowerShell from the Microsoft Store, Task Scheduler could not start `pwsh` by name, so every job failed with `0x80070002`, even at the lock screen. `lfmap jobs doctor` gains a `pwsh` check that also flags tasks registered with plain `pwsh`.

### Changed

- CLI and MCP decide approvals by tier (ADR-017). Operations declared `local_write` (T1) now run without a prompt and are logged to `audit.jsonl`. T2 asks: a terminal prompt or `--yes` in the CLI; `serve mcp --approve` (now valid for 8 hours) or MCP elicitation. T3 needs a grant, or a prompt in an interactive terminal; `--yes`, `--approve` and elicitation never cover it. A connection that cannot carry elicitation is refused, not allowed.
- CLI and MCP now expand permission variables from the user config instead of none. A list variable gives one root per entry; an undefined variable grants nothing (with a warning) instead of failing the whole plugin. Relative roots are refused, and so is a root that resolves to a network path.
